01 / Overview

项目概览

AirPrinter 是面向 Windows 10/11 的 Tauri 桌面程序。它在局域网发布一个固定的虚拟打印机入口；用户在 PC 上选定一个 Windows 输出队列。Apple 客户端通过 mDNS 找到 AirPrinter 后，使用 IPP/HTTP 发送作业，由 Windows 驱动处理页面并送入当前选定的队列。

01

一个虚拟入口，一个当前目标

手机始终选择 AirPrinter。PC 上选择单个 Windows 打印队列作为输出目标；服务使用固定的 /ipp/print 资源路径。

02

切换目标只影响新作业

切换后新接收的作业绑定到新队列；已经接收的作业继续使用原目标。程序每 30 秒检查 Windows 队列状态。

02 / Use it

快速开始

1

准备 Windows 打印机

安装打印机驱动，确认 PC 本地测试页可以正常输出。USB、网络和已配对队列均可使用；PDF、XPS、OneNote、Fax 等交互式虚拟目的地不会作为实体打印机显示。

2

选择 Windows 输出目标

在程序列表中单选一个真实队列。AirPrinter 会自动发布固定虚拟入口；如 Windows 防火墙阻止访问，可单独开启局域网规则。

3

连接同一局域网

PC 可通过网线接路由器，iPhone、iPad、Mac 可用 Wi-Fi。两侧必须能互通；访客网络与 AP 隔离会阻止发现。

4

从系统打印界面选择 AirPrinter

在 Apple 设备支持打印的应用中打开系统打印界面，选择 AirPrinter。PC 切换目标不会改变手机端选择；“关闭 AirPrinter”会停止虚拟入口。

当前验证范围

固定 HTTP 虚拟入口到 Microsoft Print to PDF 的单独测试已通过；真实手机原生提交和实体打印机出纸仍未验证。

03 / Architecture

工作原理

在手机系统打印面板选择 AirPrinter、设置选项并点击打印，PC 自动接收、渲染并投递到当前目标队列。切换 PC 目标只影响新接收的作业，已接收作业保留原目标。日常使用无需下载文档、打开查看器或在 PC 再次确认；浏览器测试页仅用于连接诊断。

STEP 01检测队列Windows 驱动与能力
STEP 02广播服务mDNS / DNS-SD
STEP 03接收作业IPP over HTTP
STEP 04渲染页面PDF / JPEG / Raster
STEP 05交给驱动GDI / Windows Spooler
作业状态

IPP 先返回待处理状态，后续可查询或取消。Windows 队列消耗作业只能证明队列阶段结束，不能独立证明纸张已经输出。

04 / Protocol

协议与文档格式

环节当前实现说明
局域网发现单一固定 AirPrinter：_ipp._tcp、_universal._sub._ipp._tcp、_printer._tcpDNS-SD/mDNS 始终发布一个虚拟打印机入口；_printer._tcp 使用端口 0。
传输IPP/HTTP，固定资源路径 /ipp/print支持 Print-Job、Validate-Job、Create-Job、Send-Document（单文档）、Get-Job-Attributes、Get-Jobs 与 Cancel-Job。作业接收时绑定当前 Windows 目标。
文档格式PDF、JPEG、URF、PWG RasterPDF 使用 Windows PDF API；图像与所公布的光栅格式经渲染后由 GDI 交给驱动。
打印选项作业名、彩色、双面、份数、纸型、质量、方向、页码、缩放页码按收到的文档编号；缩放支持适合页面、填满、原始尺寸和自动模式。其余选项按 Windows 驱动能力公布；不支持的值会被拒绝。

首选 IPP 端口 631；若被占用，使用 8631–8699 中的空闲端口，并通过 DNS-SD 公布实际值。ipp:// URI 可省略默认的 631，HTTP Host 仍需指向连接端口。

兼容性声明

该项目尚未通过完整 IPP Everywhere 1.1 一致性或 Apple 实机验收。当前未发布 _print._sub._ipp._tcp，也未声称支持全部规范扩展。URF 是为了客户端互操作提供的文档格式；发现与传输仍走 DNS-SD 和 IPP。

05 / Network

网络与安全

需要连通的端口

  • UDP 5353：mDNS 发现
  • TCP 631：首选 IPP
  • TCP 8631–8699：631 被占用时的备用范围

网线与 Wi-Fi 可以连接同一路由器；需要允许设备间通信与多播。

有意开启的访问

“允许局域网访问”会触发 Windows 管理员提示。通过后，规则仅针对 AirPrinter EXE 和本地子网，覆盖 Windows Private/Public 网络配置。

IPP 端点没有身份验证；请只在可信局域网启用共享。

管理员 PowerShell 中的手动替代命令

.\scripts\enable_firewall.ps1 -Program (Resolve-Path .\src-tauri\target\debug\airprinter.exe)

使用安装版时，将 EXE 路径改为实际安装位置。打开此 HTML 文档不会修改网络或防火墙设置。

06 / Build

开发与构建

前端使用 TypeScript、Vite、Tailwind CSS 与 DaisyUI；后端使用 Rust、Tauri 2、mdns-sd、tiny_http 和 ipp。Windows 侧使用已安装的打印驱动与系统 PDF/图像 API。

在项目根目录执行

pnpm install
pnpm tauri dev
pnpm tauri build

仅构建前端可运行 pnpm build。本机依赖目录由较新 pnpm 校验时，可运行 pnpm --config.verify-deps-before-run=false run build。

07 / Verify

验证与当前边界

已本地验证

34 项 Rust 库测试通过，4 项忽略；cargo check --all-targets 通过。固定 HTTP 虚拟入口到 Microsoft Print to PDF 的独立输出测试通过。

尚未实机验证

真实手机原生打印作业提交和实体打印机出纸仍未验证。虚拟队列测试不等于真实 iPhone/iPad/Mac 与实体打印机验收。

仅接收诊断模式

可使用 airprinter.exe --receive-only "绝对路径" 将收到的文档保存为待处理作业，不调用打印驱动。该模式只用于接收链路诊断。普通模式会自动处理和投递作业，无需用户下载文档或手动打印。

协议和本地打印模拟

cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo test --manifest-path src-tauri/Cargo.toml --locked -- --include-ignored --nocapture
python scripts/diagnose_mdns.py --self-test

独立 Node.js 客户端模拟

cargo build --manifest-path src-tauri/Cargo.toml --example simulate_lan --locked
node scripts/simulate_airprint.mjs 172.22.48.1

JS 命令的 IP 应替换为本机主机专用虚拟网卡地址。此电脑的 Hyper-V 默认交换机不回送 mDNS 多播，因此该脚本将 DNS-SD 部分明确标为隔离 UDP 模拟；IPP 请求仍会访问真实 Rust 服务，且不会向虚构队列提交打印作业。

从另一台设备检查实际广播

python scripts/diagnose_mdns.py --seconds 8

资源上限：单次上传 64 MiB、光栅解码累计 512 MiB、最多 500 页、单次 Windows 投递 120 秒、最多 4 个正在处理及 32 个未结束作业。
