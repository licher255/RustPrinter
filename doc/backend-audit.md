# Backend Audit and Local Simulation Record

Date: 2026-09-23. Goal: publish physical queues backed by installed PC drivers on the local network so iPhone/iPad/Mac devices can print directly through IPP/AirPrint.

## Audit Findings and Fixes

| Original issue | Current implementation |
| --- | --- |
| PrintDialog appeared after receipt; failures opened the file in the default application | Windows.Data.Pdf / image or raster decoding → GDI → specified Windows queue; no browser or print-dialog fallback |
| One printer name was used globally and every broadcast shared `/ipp/print` | Each queue has an independent, stable, length-limited resource path; routes and jobs are bound to the actual Windows queue |
| The mDNS base service and subtype were registered twice, and the SRV hostname was confused with the service name | Associate the `_universal` PTR with the same service instance; SRV points to a normal `.local.` hostname; IPv4 addresses update automatically |
| Unregister and re-register every minute; stopping sharing was incomplete | The mDNS daemon maintains records; unregister per queue and wait for confirmation, then close the listener and daemon |
| Broadcast nonexistent AirPrinter255 and interactive queues such as PDF/OneNote | Remove the fictitious queue entry; filter known interactive destinations from the regular list |
| URF/JPEG support was falsely claimed while all data was saved as `.pdf` | Validate MIME type and signature; actually decode URF, PWG Raster, JPEG, and PDF |
| Returned job-state=completed before printing | Set pending, then processing; query the Windows spooler and report aborted when the driver fails |
| Job ID reused request-id; cancel and query returned empty responses | Independent incrementing IDs; bind Create/Send/Get/Cancel to the queue and send cancellation to Windows |
| Color/duplex/copy capabilities were hard-coded | Query Windows driver capabilities; return errors for unsupported options; map paper using driver dimensions |
| Slicing Chinese names by byte could panic | Truncate at UTF-8 boundaries; preserve the original queue name and use UUID v5 in the URI |
| Diagnostic script failed to unpack valid DNS RRs | Reworked boundary checks, compression pointers, and PTR/SRV/TXT/A/AAAA parsing; cover pointer loops and truncated packets |
| README claimed full IPP Everywhere support and recommended disabling the firewall | State the actual implementation scope; provide a script that allows the EXE on the Private profile from the local subnet |

## Specification Review and Two-Branch Options (2026-10-12)

- The two options are on `direct-printer-broadcast` and `virtual-gateway-printer`; the shared IPP/DNS-SD layer is the same, but direct broadcasting uses a queue-specific URI while the virtual entry routes using the target snapshot at receipt time. Clauses, acceptance gates, and outstanding items are in `conformance-plan.md`.
- Review of PWG 5100.14 §4.2.2: DNS-SD instance names no longer have a queue ID hash appended by default. Before publishing, reject a queue whose instance name matches an existing instance in this process to prevent `mdns-sd` from replacing the old record by fullname; automatic renaming after a collision is not implemented.
- Review of §5.1: validate a unique Host consistently at every HTTP entry point; static icons support Last-Modified, If-Modified-Since, and 304; normal IPP POST responses retain `Cache-Control: no-cache`.
- Review of §7.1: the PC software bridge publishes `ipp-everywhere-server` as a logical device. IPP `printer-make-and-model` and DNS-SD `ty`/`product` consistently use software model `AirPrinter Windows Print Bridge`, not the Windows queue name as a physical model. Unknown speed and printable margins use IPP `unknown` (0x12), no longer publishing unmeasured 1 ppm / 6.35 mm; unconfigured values still use `no-value` according to their semantics.
- Review of §9.3: `overrides-supported` previously claimed page-level overrides, but the job flow did not execute them. The false claim has now been withdrawn and client `overrides` are rejected; non-empty `document-password` is also explicitly rejected instead of silently ignored. **PDF conditionally required overrides remain unimplemented, so this is not fully conformant to IPP Everywhere 1.1.**
- Current `mdns-sd 0.11.5` supports only one subtype per service instance; registering the same fullname again replaces the existing record. Therefore the `_print` subtype beyond `_universal`, and §4.2.3 LOC/manual location configuration, remain incomplete; attribute-table tests cannot be used to claim full conformance.
